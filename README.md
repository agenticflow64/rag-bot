# Ассистент поддержки по базе знаний

Кейс из портфолио: backend-разработчик, встраивающий AI-агентов в реальную инфраструктуру.

## Задача

Первая линия поддержки торговой компании (бытовая техника, электроника, опт)
отвечает клиентам по правилам, которые размазаны по трём десяткам внутренних
документов: зоны и тарифы доставки, отсрочка для B2B, возврат технически сложных
товаров, утеря посылки. Оператор на линии ищет регламент минуту-другую, клиент
ждет. Нужен ассистент, который:

- отвечает на рабочий вопрос оператора по внутренней базе знаний;
- к каждому факту прикладывает ссылку на раздел политики: ответ проверяется одним кликом;
- честно отвечает «в базе нет ответа», вместо того чтобы галлюцинировать;
- разворачивается в привычной инфраструктуре (Docker, PostgreSQL), без внешних векторных БД.

## Решение

Классический RAG-конвейер на производственном стеке:

- **Корпус**: 29 markdown-документов базы знаний в [data/kb](data/kb):
  политика доставки (зоны, тарифы, курьеры, ПВЗ, крупногабарит), оплата (карты,
  счёт для юрлиц, отсрочка B2B), возврат и обмен, гарантия и сервис, брак и
  некомплект, условия оптовикам, FAQ сложных случаев, регламент первой линии.
- **Эмбеддинги**: локально на GPU — bge-m3 через sentence-transformers.
  Без внешних API, без платы за токены, работает офлайн.
- **Кэш эмбеддингов**: векторы хранятся в БД по хэшу чанка — повторный ингест
  того же корпуса ничего не пересчитывает.
- **Чанкинг**: по заголовкам, ~500–800 токенов, перекрытие 100.
- **Retrieval**: векторный поиск top-k (по умолчанию 5); при близости ниже
  порога — отказ без обращения к LLM.
- **Генерация**: OpenAI-совместимый API отвечает только по найденным чанкам
  и цитирует источники [n]. GLM как основной, OpenRouter как резерв —
  переключение автоматическое при недоступности.
- **Интерфейсы**: веб (FastAPI + одна страница: слева история вопросов,
  справа ответ с источниками, SSE-стриминг) и CLI (`python -m app.ask "вопрос"`).
  Ссылки из ответа ведут на сам документ базы знаний (`/kb/...`).

Подробности: [docs/architecture.md](docs/architecture.md).

### Стек

| Слой | Технология |
|---|---|
| Язык | Python 3.12+ |
| БД / векторный поиск | PostgreSQL 17 + pgvector |
| Эмбеддинги | bge-m3, локально на GPU (sentence-transformers) |
| LLM | GLM API ↔ OpenRouter (OpenAI-совместимые), автоматический fallback |
| Инфраструктура | Docker Compose |
| Тесты | pytest: 13 юнит + 8 интеграционных |

## Результат

Замер на наборе из 20 вопросов (16 по базе + 4 вне базы),
методика — `.claude/skills/rag-eval`:

| Метрика | Значение | Комментарий |
|---|---|---|
| Hit rate источника | 100 % | 16 из 16 вопросов |
| Latency полная (медиана / p95) | 4.9 с / 17.6 с | retrieval + генерация |
| Latency retrieval (медиана) | 0.02 с | эмбеддинг вопроса + векторный поиск |
| Доля отказов (вне-базовые) | 100 % | корректные «нет ответа в базе» |
| Ложные отказы | 0 шт. | вопросы с ответом, где бот отказал |

**Демо. Цифры из локальных замеров** (генерация — бесплатный тариф
LLM-провайдера и составляет основную долю latency; эмбеддинги локальные,
retrieval стабильно быстрый).

## Как запустить

```bash
cp .env.example .env        # вписать GLM_API_KEY и/или OPENROUTER_API_KEY
docker compose up -d        # PostgreSQL 17 + pgvector
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt

python -m app.ingest        # data/kb → чанки → bge-m3 на GPU → pgvector
python -m app.web           # веб-интерфейс: http://localhost:8800
```

Эмбеддинги считаются на GPU (`.env`: `EMBEDDINGS_PROVIDER=local`,
`LOCAL_EMBEDDING_DEVICE=cuda`). На машине без GPU поставьте `cpu` —
модель та же, ингест просто дольше.

CLI для скриптов и тестов:

```bash
python -m app.ask "Сколько дней заказ хранится в пункте выдачи?"
```

Тесты: `pytest` (юнит), `pytest -m integration` (нужны запущенный docker compose и ключ генерации).

## Структура

```
app/            — конвейер: chunking, ingest, retrieval, embeddings, prompts, pipeline, llm, web, ask
app/static/     — единственная HTML-страница интерфейса
scripts/        — прогон замеров качества (eval_run.py)
tests/          — юнит и интеграционные тесты (+ фикстуры мини-корпуса)
data/kb/        — база знаний: 29 markdown-документов (в git)
data/*.local    — eval-наборы и результаты (в .gitignore)
docs/           — архитектура, сценарий демо, план
```

Полный сценарий демо: [docs/demo-script.md](docs/demo-script.md).
