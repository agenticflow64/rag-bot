# RAG-бот по базе знаний

Кейс из портфолио: backend-разработчик, встраивающий AI-агентов в реальную инфраструктуру.

## Задача

Команды теряют время, отвечая на одни и те же вопросы по документации. Нужен ассистент, который:

- отвечает на вопросы по открытой документации (в базе — официальные доки FastAPI);
- всегда даёт ссылку на источник — ответ можно проверить одним кликом;
- честно отвечает «нет ответа в базе», вместо того чтобы галлюцинировать;
- разворачивается в привычной инфраструктуре (Docker, PostgreSQL), без внешних векторных БД.

## Решение

Классический RAG-конвейер на производственном стеке:

- **Ингест**: 41 markdown-файл документации FastAPI (лицензия MIT) скачивается из
  [data/links.txt](data/links.txt), режется на чанки по заголовкам (~500–800 токенов,
  перекрытие 100) → эмбеддинги → PostgreSQL 17 + pgvector (HNSW-индекс).
- **Экономия токенов**: эмбеддинги кэшируются в БД по хэшу чанка —
  повторный ингест того же корпуса не тратит ни одного вызова API.
- **Retrieval**: векторный поиск top-k (настраивается, по умолчанию 5);
  при близости ниже порога — отказ без обращения к LLM.
- **Генерация**: OpenAI-совместимый API отвечает только по найденным чанкам
  и цитирует источники [n]. Провайдеры: GLM как основной, OpenRouter как резерв —
  переключение автоматическое при недоступности.
- **Интерфейсы**: веб (FastAPI + одна страница, SSE-стриминг ответа, тёмная тема)
  и CLI (`python -m app.ask "вопрос"`).

Подробности: [docs/architecture.md](docs/architecture.md).

### Стек

| Слой | Технология |
|---|---|
| Язык | Python 3.12+ |
| БД / векторный поиск | PostgreSQL 17 + pgvector |
| LLM / эмбеддинги | GLM API ↔ OpenRouter (OpenAI-совместимые), автоматический fallback |
| Инфраструктура | Docker Compose |
| Тесты | pytest: 13 юнит + 8 интеграционных |

## Результат

Замер на наборе из 20 вопросов (16 по базе + 4 вне базы),
методика — `.claude/skills/rag-eval`:

| Метрика | Значение | Комментарий |
|---|---|---|
| Hit rate источника | 100 % | 16 из 16 вопросов |
| Latency полная (медиана / p95) | 7.6 с / 17.5 с | retrieval + генерация |
| Latency retrieval (медиана) | 0.99 с | только векторный поиск |
| Доля отказов (вне-базовые) | 100 % | корректные «нет ответа в базе» |
| Ложные отказы | 0 шт. | вопросы с ответом, где бот отказал |

**Демо. Цифры из локальных замеров** (бесплатный тариф LLM-провайдера,
генерация — основная доля latency; retrieval стабильно около секунды).

## Как запустить

```bash
cp .env.example .env        # вписать GLM_API_KEY и/или OPENROUTER_API_KEY
docker compose up -d        # PostgreSQL 17 + pgvector
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt

python -m app.download_docs # скачать документацию (data/docs)
python -m app.ingest        # чанкинг + эмбеддинги + pgvector
python -m app.web           # веб-интерфейс: http://localhost:8800
```

CLI для скриптов и тестов:

```bash
python -m app.ask "Как настроить аутентификацию по JWT?"
```

Тесты: `pytest` (юнит), `pytest -m integration` (нужны запущенный docker compose и ключи).

## Структура

```
app/            — конвейер: chunking, ingest, retrieval, prompts, pipeline, llm, web, ask
app/static/     — единственная HTML-страница интерфейса
scripts/        — прогон замеров качества (eval_run.py)
tests/          — юнит и интеграционные тесты (+ фикстуры мини-корпуса)
data/links.txt  — источники документации (data/docs и *.local — в .gitignore)
docs/           — архитектура, сценарий демо, план
```

Полный сценарий демо: [docs/demo-script.md](docs/demo-script.md).
