# RAG-бот по базе знаний

Кейс из портфолио: backend-разработчик, встраивающий AI-агентов в реальную инфраструктуру.

## Задача

Команды теряют время, отвечая на одни и те же вопросы по документации. Нужен ассистент, который:

- отвечает на вопросы по открытой документации (PostgreSQL, Spring Security docs);
- всегда даёт ссылку на источник — ответ можно проверить одним кликом;
- честно отвечает «нет ответа в базе», вместо того чтобы галлюцинировать;
- разворачивается одной командой в привычной инфраструктуре (Docker, PostgreSQL).

## Решение

Классический RAG-конвейер на производственном стеке:

- **Ингест**: markdown/docs → чанкинг → эмбеддинги → PostgreSQL 17 + pgvector.
- **Retrieval**: векторный поиск top-k релевантных чанков по вопросу.
- **Генерация**: GLM API (OpenAI-совместимый) отвечает только по найденным чанкам и цитирует источники.
- Эмбеддинги — GLM API или локально BGE-M3 (GPU RTX 5060 Ti), переключается переменной окружения.

Подробности: [docs/architecture.md](docs/architecture.md).

### Стек

| Слой | Технология |
|---|---|
| Язык | Python 3.12 |
| БД / векторный поиск | PostgreSQL 17 + pgvector |
| LLM | GLM API (OpenAI-совместимый) |
| Эмбеддинги | GLM API или локально BGE-M3 |
| Инфраструктура | Docker Compose |

## Результат

> **В разработке.** Цифры будут из локальных замеров (демо).

Что замеряем (методика — `.claude/skills/rag-eval`):

- доля ответов с корректным источником (hit rate);
- latency ответа (ингест и retrieval-часть отдельно).
