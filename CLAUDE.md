# CLAUDE.md — rag-bot

Рабочие инструкции для Claude Code в этом репозитории.

## Цель проекта

Ассистент первой линии поддержки по корпоративной базе знаний: сотрудник
задаёт рабочий вопрос (доставка, оплата, возвраты, гарантия, опт), получает
ответ со ссылкой на раздел политики. Корпус — синтетическая база знаний
торговой компании, 29 markdown-документов в `data/kb`.
Пет-проект для портфолио, делается по вечерам.

## Позиционирование кейса

Демо-кейс фрилансера-бэкендера:
**«backend-разработчик, встраивающий AI-агентов в реальную инфраструктуру»**.

Кейс в README оформляем строго по формату: **Задача → Решение → Результат**.

## Стек

- Python 3.12+
- PostgreSQL 17 + pgvector (Docker, образ `pgvector/pgvector:pg17`)
- Эмбеддинги: локально на GPU, bge-m3 через sentence-transformers
  (без внешних API); при отсутствии GPU — `LOCAL_EMBEDDING_DEVICE=cpu`
- LLM-генерация: OpenAI-совместимые API — GLM (основной)
  и OpenRouter (резерв), автоматический fallback при недоступности

## Правила (обязательные)

1. **Секреты — только в `.env`** (в `.gitignore`). Ни одного ключа в коде,
   конфигах, тестах и истории git.
2. **Git-identity локальная** в этом репо:
   `user.name "agenticflow64"`,
   `user.email "93826006+agenticflow64@users.noreply.github.com"`.
   Не трогать `--global` (там личный аккаунт). Проверять перед коммитом.
3. **Пуш только в** `agenticflow64/rag-bot`. Никаких других remote.
4. **Ничего из основного места работы**: никаких внутренних названий
   работодателя, проектов, коллег, кода и артефактов — ни в коде,
   ни в текстах, ни в комментариях.
5. **Цифры результатов помечать «демо»** — все замеры локальные,
   из собственного окружения.
6. Формат кейса в README: Задача → Решение → Результат.
7. **Корпус — в git** (`data/kb/*.md`): документы небольшие, правки политики
   должны проходить ревью. Eval-наборы (`data/*.local`) — не в git.
