# Сценарий демо-видео

Длительность: до 2 минут. Одна съёмка экрана, без монтрака.
Сначала поднять проект: `docker compose up`, прогнать ингест.

| Таймкод | Что показываем | Что говорим |
|---|---|---|
| 0:00–0:15 | Экран README на GitHub. | «Пет-проект: RAG-бот по открытой документации. Отвечает на вопросы по PostgreSQL docs со ссылками на источник. Задача — Решение — Результат, всё как в кейсе.» |
| 0:15–0:35 | Терминал: `docker compose up`, статус контейнеров, `psql` со списком чанков в pgvector. | «Разворачивается одной командой. Внутри — PostgreSQL 17 с pgvector, документация порезана на чанки и лежит в векторном индексе.» |
| 0:35–0:55 | Вопрос №1 из базы знаний, например «Как работает VACUUM в PostgreSQL?». Ответ с цитатой и ссылкой. Кликаем по ссылке — открывается нужный раздел docs. | «Спрашиваем про документацию — получаем ответ с цитатой. Ссылка ведёт на конкретный раздел: ответ можно проверить.» |
| 0:55–1:15 | Вопрос №2 из другой темы (например, про Spring Security). Затем «вне-базовый» вопрос — бот отвечает «нет ответа в базе». | «Темы переключаются свободно. А вот вопрос вне базы знаний — бот не выдумывает, а честно отказывает.» |
| 1:15–1:40 | Вывод замеров: таблица hit rate / latency (метки «демо, локальные замеры»). | «Качество замеряю на наборе из 20 вопросов: hit rate источника и latency. Цифры — из локальных замеров, это демо.» |
| 1:40–2:00 | Экран архитектурной схемы. Финальный кадр — README. | «Стек: Python, PostgreSQL + pgvector, GLM API, локальные BGE-M3 для эмбеддингов. Код и схема — по ссылке в README.» |

## Чек-лист перед записью

- [ ] `docker compose up` поднимается чисто с нуля (проверить `docker compose down -v` → up).
- [ ] Ингест прогнан, в базе > 1000 чанков.
- [ ] Оба demo-вопроса и «вне-базовый» отработаны заранее (репетиция).
- [ ] Таблица замеров заполнена и помечена «демо».
- [ ] Терминал: увеличенный шрифт, чистая тема, нет лишних вкладок.
